# Техническое задание: развитие проекта в репозитории `neuro_models`

## 1. Контекст
- Рабочий репозиторий: `neuro_models`.
- Базовый проект для доработки: исторический `cnn1`.
- Текущая отправная точка: код обучения и оценки сегментационной модели (`UNet`) перенесен в корень репозитория.
- Доступны данные:
  - `dataset/img` (в корне репозитория) содержит RGB-снимок, который требуется использовать в новой итерации обучения.

## 2. Цель работы
Расширить текущий код в `neuro_models`, добавив **до 3 дополнительных сверточных моделей** сегментации, обучить их на доступных данных (включая RGB-снимок), получить предсказания и сформировать итоговое сравнение по F-мере.

## 3. Обязательные требования
1. Сохранить базовую модель `UNet` как контрольную (baseline).
2. Добавить от 1 до 3 новых CNN-архитектур (итого не более 4 моделей вместе с baseline).
3. Рекомендуемые варианты новых моделей (можно выбрать любые подходящие):
   - `FCN` (Fully Convolutional Network);
   - `ResUNet` / U-Net с residual-блоками;
   - легковесная encoder-decoder модель (например, SegNet-like);
   - иные уместные CNN-модели сегментации.
4. Обучить все выбранные модели в сопоставимых условиях:
   - единая схема разбиения данных (train/val/test);
   - одинаковые/сопоставимые гиперпараметры (epochs, batch size, tile, stride);
   - одинаковая метрика качества: F1.
5. Использовать RGB-снимок из `dataset/img` (корень репозитория):
   - обновить загрузку данных так, чтобы при наличии RGB-изображения оно участвовало в обучении/инференсе;
   - обеспечить корректную нормализацию и согласование каналов (1-канал/3-канала).
6. Получить прогнозы для каждой модели:
   - минимум один сохраненный файл предсказания на полном изображении/на тестовой выборке для каждой модели.
7. Сформировать итоговую таблицу сравнения моделей с F-мерой:
   - колонка `model`;
   - колонка `f1_test` (или аналогично, если явно указана другая F-метрика);
   - при возможности дополнительные колонки (`precision`, `recall`, `best_threshold`, `loss`).
8. Сохранить результаты в `results/models_compare/`.

## 4. Нефункциональные требования
- Не ломать существующий pipeline, перенесенный из `cnn1`.
- Код должен быть воспроизводимым:
  - фиксировать seed;
  - сохранять отчеты и артефакты с понятными именами;
  - логировать ключевые гиперпараметры.
- Предпочтительно запускать через единый скрипт сравнения моделей.

## 5. Предлагаемая структура итоговых артефактов
- Скрипт обучения/сравнения: `training_compare_models.py`.
- Веса моделей:
  - `results/models_compare/<ModelName>/weights.weights.h5`.
- Метрики по моделям:
  - `results/models_compare/summary_metrics.csv`;
  - `results/models_compare/summary_metrics.md`.
- Предсказания:
  - `results/models_compare/<ModelName>/pred_*.png`.
- Краткий итоговый отчет:
  - `results/models_compare/report.txt`.

## 6. Критерии приемки
1. В коде `neuro_models` присутствуют и запускаются baseline + дополнительные CNN-модели (до 3 новых).
2. Для каждой модели выполнено обучение и получена F-мера.
3. Итоговая сравнительная таблица с F-мерой сформирована и сохранена в `results/models_compare/`.
4. Использование RGB-снимка из `dataset/img` подтверждено в логике загрузки данных.
5. Для каждой модели сохранены предсказания.

## 7. План реализации (итерация 1)
1. Провести аудит текущих скриптов в корне `neuro_models` и выделить общие части pipeline.
2. Реализовать/добавить фабрику моделей (`UNet`, `FCN`, `ResUNet`, `SegNetLite` или эквиваленты).
3. Адаптировать загрузчик данных под RGB-вход (с fallback на grayscale).
4. Реализовать единый цикл обучения и оценки с расчетом F1.
5. Сохранить предсказания и отчеты по каждой модели.
6. Собрать финальную таблицу метрик и краткий сравнительный вывод.

## 8. Ограничения и допущения
- Датасет может быть небольшим, поэтому допустимо использование патчей (tile/stride).
- Если отдельная модель (например, YOLO) требует принципиально иной формат разметки, допускается заменить ее на более релевантную сегментационную CNN, чтобы сохранить сопоставимость по F1.
- При нехватке VRAM допускается уменьшение batch size и/или размера патчей при фиксировании этого факта в отчете.

## 9. Definition of Done
Работа считается завершенной, когда в `results/models_compare/` лежит итоговая таблица сравнения F-мер по всем выбранным моделям, сохранены предсказания каждой модели, и код повторно запускается на текущем репозитории без ручных правок.
